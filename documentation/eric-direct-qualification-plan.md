## Reproducible validation-only runbook

1. **Pin the run.** Record repository commit, fixture version, SDK release, bridge executable and API/plugin SHA-256 hashes, OS/architecture, taxonomy archive digest and entry points. Use an authorized installation supplied after developer approval; store no proprietary package in the public repository. Confirm current test-identity and validation-mode rules from that release's documents.
2. **Create a disposable fixture.** Set an explicit fresh test `DATABASE_URL` and filesystem `DOCUMENT_STORAGE_ROOT` under a task-owned directory. Never use `accounting.db`, its sidecars or localhost:3000. Prefer a server-level fixture; if UI generation is used, port **3114** belongs to this task and the URL, DB and storage must be verified before browser actions. Reuse the close/export journey in [`e2e/annual-close-real.spec.ts`](../e2e/annual-close-real.spec.ts) and its [`EBalancePage`](../e2e/e-balance-page.ts), extended to a 2026 UG. Use synthetic values from the start, not a redacted live-company export. Fix generation time and fiscal period so output can be reproduced.
3. **Generate through the real app path.** After #36, produce the 2026 approved/current close and retain the actual downloadable package with its reconciled dataset. Require supported GCD, exact dates, signed/contextual facts, uncondensed balances, tax-balance or book-to-tax adjustments, asset information and UG equity/result treatment. A toy XBRL string or the lifecycle emulator is not this fixture. For a full calendar year, use an isolated test clock after year end rather than bypassing the close-date guard.
4. **Bind bytes, not just values.** Retain `export.zip`, its unmodified extracted XBRL, the manifest, and the ERiC envelope. Include archive hash, XBRL hash, close-generation/report version, envelope hash, taxonomy digest and serializer commit in one run record. If schema references must change from ZIP-relative to official ERiC references, retain both forms, the exact transformation version, and a parsed comparison asserting that all facts, contexts and units are identical. Any other change invalidates the binding. Never silently regenerate from mutable ledger state. Seed authorized test identities before generation so later replacement cannot change qualified bytes.
5. **Run only validation.** D2 must call `runEric(envelope, { send: false, configuration })` with explicit bridge/runtime/manufacturer/test settings and no certificate/PIN. Verify the SDK's validation flag and add a test that the native request cannot select sending. Use a validation-only runner/network policy where permitted by the SDK. No TEST transmission is authorized by this plan. The current `pnpm test:contract:eric` runs only the sample smoke contract; after D2 it must additionally run the app-output cases, and a disabled/skipped contract must fail a claimed qualification job.
6. **Prove both outcomes.** Require zero status for the positive 2026 output, documented successful content-validation diagnostics, `sent:false`, and no transmission receipt. For the negative case, alter a known mandatory fact/type identified in the official schema/rules, recompute its hash, and require a documented content rejection tied to that mutation. A missing-DLL error, transport failure or test-marker-only response cannot satisfy either content case. Keep a separate official sample run to distinguish installation problems from serializer defects.
7. **Retain a reviewable record.** Save success **and failure** evidence with expected/observed status, structured diagnostic identifiers, runtime tuple, all hashes, fixture/close identity, timestamp and command. Keep raw synthetic artifacts and logs in restricted evidence storage; publish only reviewed summaries/digests. The existing structural previews and status-text hashes help avoid leakage but are insufficient to diagnose every failure. Do not retain PINs/certificates, live business data or assume regex redaction covers all values. Preserve evidence before `runEric` removes temporary files.
8. **State the result narrowly.** Record `VALIDATED_LOCAL_ERiC_2026` only for the exact passing tuple/artifact. It is neither Finanzamt acceptance nor proof of correctness for all company facts. Changed runtime/plugin/taxonomy/generator or close bytes require a new run. [#31](https://github.com/SanjoSolutions/accounting/issues/31) remains open until its separately authorized TEST submission/receipt, negative case, retry/correction and version-binding requirements are met. Live submission needs another explicit owner action.

Minimum proposed manifest fields (a design contract, not an existing API): `schemaVersion`, `repositoryCommit`, `fixtureId`, `fixtureVersion`, `fiscalYearStart`, `fiscalYearEnd`, `closeGenerationId`, `reportVersion`, `archiveSha256`, `exportXbrlSha256`, `ericXbrlSha256`, `envelopeSha256`, `schemaReferenceTransformVersion`, `taxonomyArchiveSha256`, `sdkVersion`, `bridgeSha256`, `apiSha256`, `pluginSha256`, `case`, `expectedStatus`, `observedStatus`, `diagnosticIds`, `send:false`, `recordedAt`, `authority:VALIDATION_ONLY_NOT_FINANZAMT_ACCEPTANCE`. The manifest must be verified against retained bytes before executing the bridge.

Bitte teilen Sie uns mit, welche Bedingungen für die interne Nutzung, die Bereitstellung unserer Software und eine etwaige Weitergabe der ERiC-Laufzeit gelten und ob hierfür zusätzliche Freigaben erforderlich sind.
